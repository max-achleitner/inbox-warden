# 0.7.0 Install Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Claude Desktop extension and the Claude Code plugin installable and understandable for a first-time user, based on the owner's real install test of 0.6.0 on 2026-10-20.

**Architecture:** The release ships the `.mcpb` unsigned and checks it with the same strict ZIP reader Claude Desktop uses. The install form (`mcpb/manifest.json`) shrinks to self-explanatory English titles with switches; `applyBundleEnv` maps the switches onto the existing `IMAP_MCP_*` variables, so `loadConfig` stays unchanged except for the locale fallback. A configuration error no longer kills the stdio server: it starts a two-tool "setup problem" server whose answers tell Claude what to tell the user.

**Tech Stack:** TypeScript (ESM, Node ≥ 20.19), MCP SDK v2 (`@modelcontextprotocol/server`), vitest, `@anthropic-ai/mcpb@2.1.2` CLI, yauzl 3 (new devDependency).

**Spec:** the Decisions section below (owner test session 2026-10-20; evidence in memory `desktop-install-findings`).

## Decisions (the spec)

- D1 No code-signing certificate. 0.7.0 `.mcpb` is unsigned; checksums and build attestation stay. Reason: `mcpb sign` 2.1.2 appends the signature after the ZIP end record with comment length 0, and Claude Desktop 3.1623 opens the whole file with yauzl's strict check ("Invalid comment length. Expected: 1872. Found: 0") — the signed 0.6.0 bundle cannot be installed. Desktop's PKCS#7 check (node-forge `verify()`) always throws, so Desktop never shows "signed" anyway.
- D2 A CI check opens every built and every released `.mcpb` the way Desktop does (yauzl 3 `open`, all entries, `manifest.json` present).
- D3 Install form titles are **English only**, short, understandable without the description (Claude Code shows titles only, no descriptions, no defaults).
- D4 No dropdowns exist in MCPB (`user_config` types: string, number, boolean, directory, file). Use switches instead of comma lists.
- D5 Form fields, in this order: Email address *, Password (Gmail: app password), Your name (optional), Claude may send email [switch, off], Claude may move email to Trash [switch, off], Locked folders (comma-separated), Attachment folders (optional), Download folder (optional), Advanced: incoming server (IMAP), Advanced: outgoing server (SMTP), Advanced: login name, if different, Advanced: don't look up servers online [switch, off].
- D6 Removed from the form: sign-in method, OAuth client ID, Microsoft 365 tenant, OAuth client secret (Microsoft 365 / Google Workspace move to the command-line version), IMAP port, SMTP port (now `host:port` in the server fields), permissions (replaced by the two switches; read and write are always on), sending mode (always `confirm`), language (from the operating system).
- D7 With "don't look up servers online" on, the built-in provider table (Gmail, GMX, iCloud, …) still applies; only DNS/MX and Mozilla autoconfig lookups are skipped.
- D8 A configuration error at stdio start-up must not end the server: Claude must be able to explain the problem and the fix.
- D9 Folder-lock and blocked-domain refusals no longer say "your administrator's policy".
- D10 Docs: Desktop install = Profile → Settings → Extensions, drag the `.mcpb` into the field (no double-click: the Microsoft Store app registers no `.mcpb` file type); change settings = … → Inbox Warden → **Configure**; after saving, a new chat is enough (Desktop restarts the extension). Locks ignore upper/lower case. Gmail: "Show search options" is the sliders icon at the right end of the search box; alternative path Settings → "Filters and Blocked Addresses" → "Create a new filter".
- D11 Install description short; the bundle gets an icon; Microsoft 365 is no longer advertised for the extension.

1. **Upgrade from 0.6.0 with saved old settings** (Desktop keeps `permissions: "read,write,delete"`, `auth_method: "microsoft"`, `send_mode: "direct"`, but no longer passes them): the server starts with read+write only; an OAuth user gets the setup-problem answer, not a dead server. 5. **Lookups off with an unknown domain and no server** — the answer tells the user to fill "Advanced: incoming server (IMAP)" or switch the lookup back on. Test in Task 2.

Rules:
- One switch parser for `IMAP_MCP_NO_AUTOCONFIG`, `IMAP_MCP_ALLOW_SEND`, `IMAP_MCP_ALLOW_DELETE`: `true`/`1` → on, `false`/`0` → off (case-insensitive); a placeholder was already removed (= off); anything else throws `BundleConfigError` `"<label>" must be on or off — not "<value>".`
- When either `ALLOW_*` variable is present and `IMAP_MCP_PERMISSIONS` is not: `IMAP_MCP_PERMISSIONS = read,write` plus `send`/`delete` for the switches that are on. An explicit `IMAP_MCP_PERMISSIONS` (containers) wins. Both `ALLOW_*` variables are deleted afterwards.
- Host fields: `name:port` splits into host and `*_PORT` (`[v6]:port` too); a value with more than one `:` and no brackets is a bare IPv6 host; when `*_PORT` is also set (containers) and differs from the port in the host, throw `BundleConfigError` naming both; `host:`, `:993`, port outside 1–65535 or non-numeric throw `BundleConfigError` `"Advanced: incoming server (IMAP)" must be a server name, optionally with :port (1–65535) — not "<value>".` (SMTP analogous).
- The empty-password message becomes `Enter the password (or app password) for <email> in the settings.` (the sign-in method is no longer in the form).
- `configFromEnv`: `locale` = `IMAP_MCP_LOCALE` if set, else `detectLocale(env)` from `src/cli/messages.ts`.
